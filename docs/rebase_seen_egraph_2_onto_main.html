Rebasing seen-egraph-2 onto latest main

A record of the conflicts hit and the judgement calls made. Nothing was pushed.

TL;DR — All 14 branch commits replayed cleanly onto the current main. The branch really was just the SeenTracker / seen-egraph feature (plus a bench-tooling commit). The only friction was that main has since deleted the debug-log / search-tree-log feature, which the branch was still built on top of. The resolution was to drop the branch's now-orphaned debug-log code and keep only its genuine additions (SearchStats + the seen-egraph). The result compiles, is fmt-clean, and touches the exact same 20 files as the pre-rebase branch (only scripts/bench_pr.py grew, by 11 lines, from one small reconciliation described below).

3 · Judgement calls

drop keep A. Discard the branch's debug-log / tree_log code; keep only SearchStats

This is the central call. The branch's best_first.rs still carried the entire debug-log scaffolding (a tree_log: Option<SearchTreeLog> field, the let tree_log = if debug { … } builder that reads Node.parent/cost/expanded and expansion_order, and the SearchTreeLog/TreeNodeLog imports) — all of which main deleted. Alongside it the branch added its genuinely new field, stats: SearchStats.

Resolution: take main's deletion wholesale and keep only the stats field and its builder. Keeping tree_log would not compile (debug_log.rs no longer exists, and the Node fields it reads are gone).

Why this is safe: the branch's actual contribution here is SearchStats/SeenStats, not tree_log — tree_log predates the branch (it lived in the merge-base) and the branch never modified it, it just carried it along. Verified afterwards: no debug_log / tree_log / SearchTreeLog reference survives anywhere in src/ or run.py.

merge B. Keep both pruning mechanisms — FootprintTracker and the seen-egraph

Both main (footprint dedup-by-match) and the branch (seen-egraph) inject pruning state into the same two spots of best_first.rs: the tracker initialisation next to the heap, and the ═══ STATS ═══ print block. They are independent prunes, so both were preserved:

  • Init: kept the branch's seen closure (which lifts the DSRs and builds the SeenTracker) and main's let footprints = args.opt_dedup_by_match.then(FootprintTracker::new) line side by side.
  • Stats: merged the output so the run prints the seen-set hit breakdown, the ── seen-egraph audit ── block (branch), and the footprint-set counters (main). Seen-related output is grouped together, footprint after.

merge C. lib.rs — new flags from both sides coexist

The branch rewrote --opt-seen (opt-in) into --no-opt-seen (on by default) and added the --seen-egraph-saturate / -every / -dynamic / --seen-egraph-decides flags. main added --no-opt-dedup-by-match right after opt_seen and removed --debug-log. All of these are non-overlapping in intent, so every flag was kept; only the debug-log arg was dropped (per call A). The module-declaration block and the multiple_step_search stats threading auto-merged.

reconcile D. bench_pr.py — two independent "skip SMC" selectors (only place new glue code was written)

Both sides independently added a way to restrict which methods run, and both assign to the same methods variable:

  • main (#299): a CLI flag --method bfs|smc|both (default both) → methods = {…}[a.method].
  • branch: a module constant DO_SMC = False (documented as "runs only best-first") → methods = ["enum","smc"] if DO_SMC else ["enum"], plus a WORKTREES single-run mode.

Naively keeping both would define methods twice, with the branch's line silently clobbering main's --method flag. Dropping the branch's line instead would leave DO_SMC printed in the run header but doing nothing — a latent bug either way.

Resolution: made the two cooperate — --method wins when passed, otherwise the effective method falls back to the DO_SMC toggle:

method  = a.method if a.method is not None else ("both" if DO_SMC else "bfs")
methods = {"bfs": ["enum"], "smc": ["smc"], "both": ["enum", "smc"]}[method]

I also took the branch's fuller if WORKTREES: … else: … output block (its single-run/fmt_single_table path — which already contained main's methods= keyword args) and the branch's fmt_table signature (all call sites pass methods= by keyword, so parameter order is immaterial).

Behavior note worth confirming: the default method selection now follows the branch's DO_SMC=False (best-first only), not main's old both default. Pass --method both for the full side-by-side run. This is the only spot where I wrote reconciling code rather than choosing one side verbatim, and the reason bench_pr.py is +11 lines vs the original branch.

left as-is E. Vestigial _debug.json filter in viz/analysis.js

The branch's connection-pooled results loader filters out files ending in _debug.json. Now that main has removed debug-log output, that suffix is never produced, so the filter is a harmless no-op. I left it untouched to keep the rebase faithful/minimal; it can be swept up in a later cleanup.
